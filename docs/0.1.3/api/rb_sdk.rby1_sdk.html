rb_sdk.rby1_sdk.base module#

RB-Y1 SDK 베이스 — 후보 model 전부에 대해 ``RBY1ClientSDK``를 미리 connect.

RB-Y1은 사이트당 1대 운용이지만 model이 a/m/ub 중 무엇인지 모를 수 있다. 부팅 시점에 후보 model 전부로 create_robot() + connect()``를 시도해 ``_clients dict에 넣어두고, 함수 호출 시 들어오는 ``robot_model``로 lookup한다. 잘못된 model로 만들어진 client에 method를 호출하면 서버 측에서 no reply/에러가 나므로 자연스럽게 걸러진다.

비동기 정책:

공식 rby1_sdk (PyPI 0.9.1)는 C++/pybind11 + sync gRPC stub이라 async 컨텍스트에서 그냥 호출하면 이벤트 루프가 막힌다. 따라서 SDK의 public 호출 메서드는 모두 async def``로 정의하고 내부에서 ``asyncio.to_thread 로 worker thread에 위임한다. 자세한 근거는 backend/packages/rb_sdk/src/rb_sdk/rby1_sdk/README.md 참조.

rb_sdk.rby1_sdk.client.extract_log_message(raw)[소스]#

서버 로그 한 줄에서 사람이 읽을 사유만 뽑아낸다.

rby1_sdk 의 검증 실패 로그는 "[timestamp] [Component] Invalid request: {...중첩 JSON...}" 형태고, 실제 이유는 그 JSON 맨 안쪽 control.control...control.message 에 깊이 묻혀 있다(라이브 확인 — nesting 깊이는 어느 컴포넌트/커맨드 타입이냐에 따라 달라진다). 로그 뷰어에 그 JSON 덩어리를 통째로 보여주면 못 읽으므로, JSON 을 파싱해서 가장 안쪽 message 키만 재귀적으로 찾아 반환한다. JSON 이 없는 일반 로그(예: ControlManager 상태 메시지)는 맨 앞 자체 타임스탬프만 떼고 나머지는 그대로 돌려준다.

공식 rby1_sdk``의 ``robot.start_state_update(cb, rate) 래퍼. on_state``는 ``rate Hz로 호출되며 인자는 1개(robot_state) 또는 2개(robot_state, control_manager_state)를 받을 수 있다.

콜백에 넘어오는 인자는 **raw pybind 객체**다. dict로 변환하려면 콜백 안에서 RBRby1StateSDK.robot_state_to_dict(...) / RBRby1StateSDK.control_manager_state_to_dict(...) 를 호출할 것.

주의: on_state 콜백은 gRPC 핸들러 **전용 스레드**에서 호출된다 — 블로킹/무거운 작업 금지. asyncio 루프로 값을 넘기려면 loop.call_soon_threadsafe 등으로 직접 브릿지할 것.

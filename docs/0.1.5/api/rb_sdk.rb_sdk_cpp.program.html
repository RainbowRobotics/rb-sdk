make_script(self: rb_sdk.rb_sdk_cpp.RBProgramSDK, *, mode: str = 'ADVANCED', contents: str | None = None, flow_manager_args: object = None) → None#

Runs a program script step, in either GENERAL or ADVANCED mode.

In GENERAL mode, flow_manager_args's “general_contents” argument is evaluated as a single expression against the step’s context (assignments are reflected into state). In ADVANCED mode, contents is compiled and executed as an arbitrary python script with variables/var, update_variable, update_var/update, get_var/get, done, pause, stop, resume, check_stop, and rb_log injected into its globals (the bridge builds that env from flow_manager_args; compile/exec runs on the PyFM side in ctx.run_advanced_script). rb_log is this SDK’s own log (RBBaseSDK::log), called as rb_log(content, robot_model, level).

Parameters:

  • mode – “GENERAL” or “ADVANCED”.

  • contents – ADVANCED-mode script source. Required when mode is “ADVANCED”.

  • flow_manager_args – PyFM step context. Required; the step is marked done when the script finishes (or immediately raises, in ADVANCED mode, since the step is still marked done before the exception propagates).

Raises:

std::runtime_error – If GENERAL mode is missing “general_contents”, or ADVANCED mode is missing contents.

rb_sdk.rb_sdk_cpp.execute_mc_read(*, rpc: rb_sdk.rb_sdk_cpp.RpcManager, module_name: str, server_ip: str, server_port: int, register_addr: int, address_type: str, protocol: str, function_code: int, number_of_read: int, return_variable_name: str, resolve_option: str = 'SKIP', flow_manager_args: rb_schemas.sdk.FlowManagerArgs | None = None, alarm_fn: Callable[[str, str], None] = None) → rb_sdk.rb_sdk_cpp.RpcResult#

Reads MC (Mitsubishi) protocol device values.

function_code selects the command: 1 reads bit devices (read_bit), 2 reads word devices (read_word). address_type and protocol resolve the target McDeviceType and McFrameType respectively. The result is always taken from RpcResult::data_word — unlike the Python original’s data_word or data_bit fallback, a bit read does not fall back to data_bit (matches the current C++ behavior).

Parameters:

  • rpc – RpcManager handle for the target connection, obtained via RBProgramSDK::get_rpc(module_name).

  • module_name – PyFM task id identifying the calling step/task.

  • server_ip – MC server IP address.

  • server_port – MC server port.

  • register_addr – Starting device address to read from.

  • address_type – Device type: “1”/”D”, “2”/”M”, “3”/”X”, or “4”/”Y”.

  • protocol – MC frame type: “1”/”MC_1E” or “2”/”MC_3E”.

  • function_code – 1 (read_bit) or 2 (read_word).

  • number_of_read – Number of devices to read.

  • return_variable_name – PyFM variable name that will receive the read values (RpcResult::data_word).

  • resolve_option – How to handle a failed read — “SKIP” continues without effect, “STOP” raises immediately, “ASK” fires alarm_fn and pauses the PyFM context (requires flow_manager_args). Defaults to “SKIP”.

  • flow_manager_args – Optional PyFM step context. return_variable_name is written into its context and flow_manager_args.done() is called on completion (unless resolve_option is “STOP” and the read failed, which raises instead).

  • alarm_fn – Optional (title, content) callback used only when resolve_option is “ASK”.

Returns:

RpcResult from the native call (success flag plus the read values in data_word).

Raises:

std::runtime_error – If function_code is not 1 or 2, or address_type/@p protocol cannot be resolved; and, under “STOP”, if the read fails.

  • protocol – MC frame type: “1”/”MC_1E” or “2”/”MC_3E”.

  • function_code – 3 (write_bit) or 4 (write_word).

  • payload_field – List of values to write (1-40 entries), range depends on function_code as described above.

  • resolve_option – How to handle a failed write — “SKIP” continues without effect, “STOP” raises immediately, “ASK” fires alarm_fn and pauses the PyFM context (requires flow_manager_args). Defaults to “SKIP”.

Sends data over a socket connection.

function_code selects how payload is encoded before sending: 3 (BYTES) splits payload on the delimiter read from flow_manager_args.args[“data”][“split”] and parses each token as an integer byte value; 4 (ASCII) encodes payload directly as ASCII bytes.

Parameters:

  • rpc – RpcManager handle for the target connection, obtained via RBProgramSDK::get_rpc(module_name).

  • module_name – PyFM task id identifying the calling step/task.

  • server_ip – Socket server IP address.

  • server_port – Socket server port.

  • function_code – 3 (BYTES, delimiter-split) or 4 (ASCII).

  • payload – String payload to send; interpretation depends on function_code as described above.

  • resolve_option – How to handle a failed send — “SKIP” continues without effect, “STOP” raises immediately, “ASK” fires alarm_fn and pauses the PyFM context (requires flow_manager_args). Defaults to “SKIP”.

  • flow_manager_args – Optional PyFM step context, required when function_code is 3 to look up the split delimiter. flow_manager_args.done() is called on completion (unless resolve_option is “STOP” and the send failed, which raises instead).

  • alarm_fn – Optional (title, content) callback used only when resolve_option is “ASK”.

Returns:

RpcResult from the native call.

Raises:
